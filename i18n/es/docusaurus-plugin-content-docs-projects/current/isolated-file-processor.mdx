# 🛠️ SupportShield — Procesador de archivos aislado

**En desarrollo — no está listo para producción.**

Estoy trabajando en SupportShield para explorar el procesamiento asíncrono de archivos adjuntos no confiables sin ejecutar analizadores de archivos dentro de la aplicación pública.

- 💻 [Código fuente en GitHub](https://github.com/dsanchezcr/isolated-file-processor)

## Caso de uso

Está pensado para **flujos de soporte** que reciben archivos adjuntos de clientes. En lugar de abrir un archivo subido directamente en otra herramienta, el sistema lo pone en cuarentena, intenta reconstruir y validar su contenido de forma aislada y permite continuar el procesamiento solo con los resultados validados.

## Cómo funciona

- Una puerta de enlace con autenticación recibe los archivos en un almacenamiento privado de cuarentena y encola tareas de procesamiento.
- Un proceso de trabajo en un host de ejecución dedicado inicia contenedores Docker desechables, sin acceso a la red y con límites de recursos.
- Los analizadores se ejecutan dentro de esos contenedores; solo los resultados reconstruidos y validados pueden llegar al almacenamiento de archivos procesados.
- Si el procesamiento falla, se rechaza el archivo en lugar de recurrir al original.

El proyecto utiliza **Node.js, Docker, BullMQ, Redis, almacenamiento e infraestructura de Azure**.

## Limitaciones actuales

Es un proyecto experimental, no un servicio de procesamiento de archivos listo para desplegar. Azure Container Apps puede alojar la puerta de enlace, pero no puede ejecutar el entorno aislado de Docker actual; para ello se necesita un host de ejecución dedicado. Aún deben resolverse requisitos de despliegue, imágenes de dependencias y licencias antes de usarlo en producción.

El aislamiento reduce el riesgo, pero **no es un antivirus ni garantiza resultados inofensivos**. Consulta la arquitectura, el modelo de amenazas y la documentación de despliegue del repositorio para conocer los límites actuales.
