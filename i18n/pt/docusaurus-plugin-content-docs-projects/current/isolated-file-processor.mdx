# 🛠️ SupportShield — Processador de arquivos isolado

**Em desenvolvimento — não está pronto para produção.**

Estou trabalhando no SupportShield para explorar o processamento assíncrono de anexos não confiáveis sem executar analisadores de arquivos dentro do aplicativo público.

- 💻 [Código-fonte no GitHub](https://github.com/dsanchezcr/isolated-file-processor)

## Caso de uso

Ele foi pensado para **fluxos de suporte** que recebem anexos de clientes. Em vez de abrir um arquivo enviado diretamente em outra ferramenta, o sistema o coloca em quarentena, tenta reconstruir e validar seu conteúdo de forma isolada e permite continuar o processamento apenas com os resultados validados.

## Como funciona

- Um gateway com autenticação recebe arquivos em um armazenamento privado de quarentena e enfileira tarefas de processamento.
- Um processo de trabalho em um host de execução dedicado inicia contêineres Docker descartáveis, sem acesso à rede e com limites de recursos.
- Os analisadores são executados dentro desses contêineres; apenas os resultados reconstruídos e validados podem chegar ao armazenamento de arquivos processados.
- Se o processamento falhar, o arquivo é rejeitado em vez de recorrer ao original.

O projeto utiliza **Node.js, Docker, BullMQ, Redis, armazenamento e infraestrutura do Azure**.

## Limitações atuais

Este é um projeto experimental, não um serviço de processamento de arquivos pronto para implantação. O Azure Container Apps pode hospedar o gateway, mas não pode executar o ambiente isolado de Docker atual; isso exige um host de execução dedicado. Os requisitos de implantação, imagens de dependências e licenciamento ainda precisam ser resolvidos antes do uso em produção.

O isolamento reduz o risco, mas **não é um antivírus e não garante resultados inofensivos**. Consulte a arquitetura, o modelo de ameaças e a documentação de implantação do repositório para conhecer os limites atuais.
